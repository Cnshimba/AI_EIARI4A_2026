WEEK 12

Final Project & Presentation

Module: Artificial Intelligence (AI)
Level: Undergraduate (Final Project)
Weight: 40%
Duration: 4 weeks
Submission: Jupyter Notebook + Technical Report
Prerequisite: Midterm Project (ML-based IDS on flow CSV)

Learning Outcomes
By the end of this project, you will be able to:
1. Extract flow-level features from raw PCAP data (Zeek/CICFlowMeter).
2. Design a Deep Learning pipeline for Intrusion Detection (IDS).
3. Implement both Supervised (Binary Classification) and Unsupervised (Autoencoder) models.
4. Evaluate the security implications of your model (False Positives vs. Negatives).


Week 12 Goal:
This is it—the culmination of your semester. You will combine your cybersecurity knowledge with your new AI skills to build an End-to-End Intrusion Detection System (IDS). You will take raw network traffic (PCAP), clean it, engineer features, and train a Deep Learning model to hunt for attacks. This mirrors the real-world workflow of a Security Operations Center (SOC) analyst or AI Security Engineer.

1. Big Picture Progression (Very Important)

Students now complete the entire security ML pipeline:

PCAP
 ↓
Traffic Feature Extraction
 ↓
Data Cleaning & Engineering
 ↓
Deep Learning Models
 ↓
Intrusion Detection

This closes the loop that started in Week 1.

2. Final Project Scenario

Your organisation suspects malicious activity on its internal network.

A packet capture (PCAP) was taken at the network gateway.

You are tasked with:

  1. Extracting meaningful features from the PCAP
  2. Preparing the data for Deep Learning
  3. Designing a Deep Learning–based Intrusion Detection System (DL-IDS)
  4. Detecting suspicious network behaviour

This mirrors real SOC and blue-team workflows.

3. Learning Outcomes (Final-Level)

By the end of this project, students must demonstrate:

  1. Understanding of PCAP structure
  2. Ability to extract flow-level features
  3. Ability to design DL pipelines for security
  4. Understanding of temporal and behavioural attacks
  5. Cybersecurity-driven interpretation of AI results

4. Tools & Constraints (Pedagogically Important)

Mandatory Tools

  • tcpdump (capture understanding)

  • Zeek OR CICFlowMeter (feature extraction)

  • Python (NumPy, Pandas, Matplotlib)

  • TensorFlow / PyTorch

Explicitly NOT Required

❌ Writing packet parsers
❌ Deep protocol decoding
❌ Real-time systems

Focus is security analytics, not packet engineering.

5. Provided Resources

Students receive:

traffic_capture.pcap

Optionally:

attack_capture.pcap

PCAP is small (5–20 MB) and curated.

6. Project Structure (Graded Pipeline)

Part A: Understanding PCAP & Traffic Flows (10%)

Students must explain (Markdown):

  • What a PCAP file contains

  • Difference between packets and flows

  • Why raw packets cannot be used directly in ML

  • Why feature extraction is required

No code here.

Part B: PCAP → Flow Feature Extraction (20%)

This is the core upgrade from the midterm.

Option 1 (Recommended): Zeek

zeek -r traffic_capture.pcap

Students must:

  • Identify generated logs (conn.log, http.log, etc.)

  • Convert conn.log to CSV

zeek-cut < conn.log > flows.csv

Option 2: CICFlowMeter (Alternative)

java -jar CICFlowMeter.jar -f traffic_capture.pcap -c flows.csv

Required Deliverables

Students must:

  • Explain what features were extracted

  • Identify flow identifiers

  • Justify feature relevance to intrusion detection

Marks are for understanding, not tool mastery.

Part C: Data Cleaning & Feature Engineering (15%)

Students now repeat Week 1 + Midterm skills, but on real data.

Required tasks:

  • Handle missing values

  • Remove duplicates

  • Fix inconsistent protocol labels

  • Create at least one new feature, e.g.:

df["bytes_per_packet"] = df["total_bytes"] / df["total_packets"]

Explain security relevance.

Part D: Deep Learning Model 1 — Supervised IDS (20%)

Students must build a fully connected neural network.

Dataset

  • Label traffic as:

  • benign

  • suspicious
    (Labels may be provided or rule-derived.)

Architecture

  • Input: flow features

  • Hidden layers: ReLU

  • Output: Sigmoid

Explain:

  • Loss function

  • Activation choices

  • Overfitting risks

Part E: Deep Learning Model 2 — Autoencoder IDS (Unsupervised) (20%)

This is the cybersecurity centerpiece.

Why Autoencoders?

  • Detect unknown attacks

  • Learn “normal traffic behaviour”

  • Widely used in real IDS research

Requirements

  • Train only on benign traffic

  • Compute reconstruction error

  • Define anomaly threshold

  • Flag suspicious flows

This directly links to zero-day attack detection.

Part F: Evaluation & Security Interpretation (10%)

Students must:

  • Compare:

  • ML (Midterm)

  • Supervised DL

  • Autoencoder DL

  • Discuss:

  • False positives vs false negatives

  • Alert fatigue

  • Real deployment challenges

Part G: Reflection & Future Work (5%)

Students must answer:

  • What attacks would this system miss?

  • How could attackers evade detection?

  • How would raw packet DL (CNNs) improve this?

  • What are ethical risks of automated IDS?

9. Expertise You Will Acquire After This Project

Completing this project demonstrates mastery of the following high-demand skills:

  • End-to-End Pipeline Engineering: Moving from raw binary data (PCAP) to actionable AI insights.

  • Real-World Cybersecurity Workflow: Applying AI not just as a math exercise, but as a tool for Security Operations (SOC).

  • Advanced Deep Learning Architecture: Implementing Autoencoders for anomaly detection (Zero-Day defense).

  • Critical Evaluation: Distinguishing between statistical success and security reality (addressing False Positives).

  • Industry & Research Alignment: Using tools (Zeek, PyTorch) and methods found in top-tier security research.
