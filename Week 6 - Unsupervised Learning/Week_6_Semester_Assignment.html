Unsupervised Learning

Week 6 Semester Assignment
Assignment Goal: To build a complete Machine Learning Pipeline that detects malicious network traffic.
This assignment assesses your mastery of Weeks 1-6 (Python, Data Analysis, Visualization, Supervised Learning, and Unsupervised Learning).

Scenario
You are a Junior AI Engineer at a Cybersecurity Firm.
Your Security Operations Center (SOC) has captured NEW network traffic logs from a recent incident (semester_project_data.csv).
Constraint: This data is raw and dirty. You must apply the ETL skills you learned in Week 3 to clean it before training your model.

1. Assignment Overview

Topic Description
Data Source semester_project_data.csv (New "Dirty" Dataset)
Task Binary Classification (Benign vs. Suspicious)
Deliverables 1. Jupyter Notebook (.ipynb)
2. Short PDF Report (2-3 Pages)
Weight 30% of Course Mark

2. The Dataset

The dataset represents extracted features from network packet captures (PCAPs).
Each row is a single "flow" (a communication between two computers).

Feature Description
flow_duration How long the connection lasted (seconds).
packet_count Total number of packets sent.
byte_count Total amount of data transferred (bytes).
protocol The protocol used (TCP, UDP, etc.).
label Target: benign (Normal) or suspicious (Attack).
The Data is Dirty: Use the skills you learned in Week 3 Lab to clean this dataset. You will need to handle the same missing values, duplicates, and inconsistencies again to prepare it for Machine Learning.

3. Assignment Requirements (The Pipeline)

You must follow this exact engineering pipeline. Marks are awarded for each stage.

Part A: Data Loading & Inspection (10%)

  1. Import Libraries: Pandas, NumPy, Matplotlib/Seaborn.
  2. Load Data: Read the CSV file.
  3. Inspect:

  • Show the first 5 rows (head).

  • Show data types and missing values (info).

  • Show statistical summary (describe).

Part B: Data Cleaning (20%)

You must clean the data before using it.
1. Missing Values:

  • Impute missing numeric values (Mean/Median).

  • Answer Strategy: Drop or impute missing categorical values (Explain your choice).
    2. Duplicates: Identify and remove duplicate rows.
    3. Standardization: Fix inconsistent naming (e.g., tcp vs TCP).
    4. Outliers:

  • Identify physically impossible values (e.g., negative duration).

  • Filter out extreme anomalies if justified.

Part C: Exploratory Data Analysis (EDA) (10%)

Visualize the data to understand attack patterns.
1. Class Balance: Bar chart of label (How many Benign vs Suspicious?).
2. Feature Relationships: Scatter plot of flow_duration vs byte_count.
3. Distributions: Histogram of packet_count.
4. Analysis: Write 1-2 sentences interpreting each plot (e.g., "Attacks tend to have short duration but high packet counts").

Part D: Feature Engineering & Preprocessing (10%)

  1. New Feature: Create bytes_per_packet = byte_count / packet_count.
  2. Encoding: Convert protocol (text) into numbers (One-Hot Encoding).
  3. Label Encoding: Convert label (benign/suspicious) to 0/1.
  4. Scaling: Normalize numeric features (Scale 0-1) so large numbers don't dominate the model.

Part E: Model Training (20%)

  1. Split Data: Use train_test_split (80% Training, 20% Testing).
  2. Train Model: Train a Logistic Regression OR Decision Tree model.
  3. Evaluate:

  • Calculate Accuracy.

  • Display the Confusion Matrix.

  • Question: Which is worse for a bank: A False Positive (Flagging normal user as hacker) or False Negative (Missed hacker)?

Part F: Unsupervised Learning (10%)

Let's see if the data naturally groups together without labels.
1. Drop Labels: Create a new X_unsupervised dataset by dropping the label column.
2. K-Means: Run K-Means Clustering with n_clusters=2.
3. Visualize: Plot flow_duration vs byte_count again, but color the points by their Cluster ID (not the real label).
4. Comparison: Does the clustering distribution look similar to the real class distribution? (Write 1 sentence).

Part G: Report (20%)

Submit a short PDF report summarizing your findings.

  • Introduction: What is the problem?

  • Methodology: How did you clean the data?

  • Results: How accurate was your model?

  • Conclusion: Would you deploy this model? Why/Why not?
