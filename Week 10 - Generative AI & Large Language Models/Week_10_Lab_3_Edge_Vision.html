Part 2: Distributed Inference (The LAN Setup)

In many labs, we have dedicated AI boards like the NVIDIA Jetson Nano. Instead of running a model on every slow laptop, we can run it on the Jetson and connect to it over the network.

2.1 Server Side: Allowing Remote Connections

By default, Ollama only listens to localhost (127.0.0.1). To allow other computers to connect, you must set an environment variable on the Jetson Service:

# On the Jetson Server (Linux)
export OLLAMA_HOST=0.0.0.0:11434
ollama serve

2.2 Client Side: Connecting via Python

Update your script's URL from localhost to the Jetson's IP address (e.g., 192.168.1.100).

import requests
import base64

JETSON_IP = "192.168.1.100" # Replace with your Jetson's actual IP

def image_to_base64(image_path):
    with open(image_path, "rb") as image_file:
        return base64.b64encode(image_file.read()).decode('utf-8')

def analyze_image_remote(image_path, prompt):
    img_b64 = image_to_base64(image_path)
    url = f"http://{JETSON_IP}:11434/api/generate"
    
    data = {
        "model": "moondream",
        "prompt": prompt,
        "images": [img_b64],
        "stream": False
    }
    
    response = requests.post(url, json=data)
    return response.json()['response']

print(analyze_image_remote("pcb_board.jpg", "Detect any burnt components."))

Part 3: Distributed VS Code Assistant

In Lab 2, we used a local model for code help. Now, we will configure the **Continue extension** to use the **Jetson Nano** on the network.

  1. Open Continue Config (config.json).
  2. Add a new model entry with the apiBase pointing to your Jetson:
{
  "title": "Jetson-Llama3",
  "model": "llama3.1:8b",
  "apiBase": "http://192.168.1.100:11434",
  "provider": "ollama"
}

Note: This allows a low-power laptop to have "Jetson-grade" intelligence without the thermal heat or battery drain of running the model locally!
