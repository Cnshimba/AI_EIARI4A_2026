Lecture Outline

Part 1: The Transformer Revolution (25 mins)

1.1 Historical Context

  • Before 2017: RNN/LSTM dominance

  • Sequential processing (one word at a time)

  • Vanishing gradients on long sequences

  • Slow training (no parallelization)

  • 2017 Breakthrough: "Attention Is All You Need" (Vaswani et al.)

  • Eliminated recurrence entirely

  • Introduced self-attention

  • Enabled massive parallelization

1.2 Self-Attention Mechanism

Core Idea: Relate every word to every other word

Example: "The animal didn't cross the street because it was too tired."

  • Query: "What does 'it' refer to?"

  • Answer: Self-attention computes that "it" relates strongly to "animal" (not "street")

Bank Disambiguation:

  • "Bank of the river" → "Bank" attends to "river"

  • "Bank for money" → "Bank" attends to "money"

Visual: Show self-attention diagram

1.3 The Math (Q, K, V)

Think of it as a differentiable database lookup:

Query (Q): What am I looking for?
Key (K): What do I offer as a match?
Value (V): What content do I provide?

Scaled Dot-Product Attention computes a weighted sum of values based on the relationship between Queries and Keys:

$Attention(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$

Steps:
1. Similarity: $Q \cdot K^T$ calculates how much each word relates to others.
2. Scaling: Divided by $\sqrt{d_k}$ to prevent gradient explosion.
3. Normalization: Softmax turns scores into probabilities.
4. Aggregation: Multiplied by $V$ to get context.

Causal Masking: In decoder models (GPT), prevent peeking at future tokens

1.4 Multi-Head Attention

Why Multiple Heads?

  • Each head learns different aspects

  • Head 1: Syntax (subject-verb agreement)

  • Head 2: Semantics (meaning relationships)

  • Head 3: Positional relationships

Implementation: Run 8-16 heads in parallel, concatenate outputs

1.5 Positional Encoding

Problem: Attention has no inherent order
Solution: Add position information to embeddings

  • Sine/cosine waves (original Transformer)

  • Learned embeddings (modern variants)

Part 2: Large Language Models (25 mins)

2.1 Training from Scratch vs. Pre-training

Training from Scratch:

  • Full control, zero external bias.
  • Con: Millions of dollars, trillions of tokens, month of compute.

Pre-training (Foundation Models):

  • Low cost, state-of-the-art weights, immediate results.
  • Con: Inherits internet bias, fixed vocabulary.
  • Practicality: 99% of projects start here.

2.2 Pre-Training: The Foundation

Objective: Predict next token

Training Data (2024-2026 models):

  • Wikipedia, books, code

  • Filtered web crawls

  • Specialized datasets (math, science)

  • Petabytes of text

What It Learns (accidentally):

  • Grammar and syntax

  • World knowledge and facts

  • Reasoning patterns

  • Code structure

2.2 Alignment: From Autocomplete to Assistant

Problem: Raw models continue text, don't follow instructions

Solution: RLHF (Reinforcement Learning from Human Feedback)

Process:
1. Humans rank model outputs (good → bad)
2. Train reward model to predict human preferences
3. Optimize LLM against reward model

Modern Alternative: DPO (Direct Preference Optimization)

  • Simpler, more stable

  • No separate reward model needed

Example Transformation:

  • Prompt: "How do I bake a cake?"

  • Pre-trained: Continues with random web text

  • Aligned: Provides structured recipe

2.3 Architectural Flavors

Encoder-Only (BERT):

  • Bidirectional (sees whole sentence)

  • Best for: Classification, NER, QA

Decoder-Only (GPT, Llama, Claude):

  • Autoregressive (left-to-right)

  • Best for: Generation, chatbots

  • Dominant architecture for modern LLMs

Encoder-Decoder (T5):

  • Both components

  • Best for: Translation, summarization

2.4 LLM Tiers: Size vs. Application

Classifying models by parameter count helps engineers select the right tool for the hardware (Pi 5 vs Server):

  • SLM (Small) [1B-4B]: Edge devices, offline private summarization (e.g., Phi-3 Mini).
  • Mid-Sized [7B-35B]: Standard chatbots, focused coding models (e.g., Llama-3 8B).
  • Large [70B+]: High-level reasoning, complex logic (e.g., Llama-3 70B).

2.5 Customization: Making it "Yours"

How to adapt a base model to your specific domain:

  • Prompting: Influencing output via the input (Zero-shot/Few-shot).
  • RAG: Retrieval-Augmented Generation. Connecting to external PDFs/DBs.
  • Fine-tuning: Updating weights on small datasets (LoRA/QLoRA).

2.6 Emergent Abilities

Phenomenon: Capabilities not explicitly trained

Examples:

  • Arithmetic (trained on text, learns calculation)

  • Translation (monolingual data, learns translation)

  • Reasoning (chain-of-thought)

Hypothesis: Scale reveals generalizable patterns

Part 3: Deployment & Optimization (20 mins)

3.1 The Challenge

Model Sizes:

  • Llama-3-8B: ~16GB (FP16)

  • Llama-3-70B: ~140GB

  • GPT-4: Unknown (estimated 1TB+)

Hardware Constraints:

  • Consumer GPUs: 4-24GB VRAM

  • Cloud instances: Expensive at scale

3.2 Quantization (The Bridge to Edge AI)

Concept: Mapping continuous mathematical space (high-precision floats) to a discrete one (integers).

Why Quantize?

  • Computational Efficiency: Integer math takes ~1 clock cycle; floating-point takes 3-4 cycles.
  • Hardware Compatibility: Edge devices (like TPUs/NPUs) often only support 8-bit integer operations.

The Memory Impact (Example: DeepSeek R1):

  • Original: 671 billion parameters in FP16 = ~720 GB VRAM.
  • Quantized: Reduced to ~131 GB (fits on two H100 GPUs instead of a massive cluster).

The Mechanics (Scale & Zero Point):

  • Calibration: Determine the min/max values flowing through the network.
  • Scale ($s$) & Zero Point ($z$): Formulas used to map real values to integer ranges (e.g., -128 to 127) while keeping zero exactly zero.

Deployment Integration:

  • Formats: GGUF (CPU-friendly), AWQ/GPTQ (GPU-optimized).
  • Lab Connection: In Lab 1, we deploy Phi-3 using Ollama, which uses quantized files to run efficiently on local laptops and Pi 5s.

3.3 Hugging Face Ecosystem

The "GitHub of AI":

  • Model Hub: 1M+ models with gated access & versioning.
  • Datasets: Curated data for evaluation/fine-tuning.
  • transformers library: Standard Python API for thousands of models.
  • Spaces: Instant deployment for demos (Streamlit/Gradio).

Key Libraries:

  • transformers: Model loading/inference

  • accelerate: Multi-GPU training

  • peft: Parameter-efficient fine-tuning

3.4 Deployment Pipeline

Standard Flow:
1. Select Model: Match to hardware
2. Tokenize: Text → IDs
3. Inference: Forward pass → logits
4. Decode: Sample token → text
5. Loop: Repeat until done

Modern Stack:

  • vLLM: High-throughput serving

  • FlashAttention: Memory-efficient attention

  • Continuous batching

Summary (5 mins)

Key Takeaways

  1. Transformers: Self-attention enables parallel processing at scale
  2. Pre-training: Next-token prediction teaches language + facts
  3. Alignment: RLHF/DPO makes models helpful assistants
  4. Decoder-only: Dominant architecture for generative AI
  5. Deployment: Quantization + Hugging Face democratize access
